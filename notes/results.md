## B.【実測】ノイズSNR段階別 CER(校正済みホワイトノイズ重畳)

> ⚠️ **2026-06-12 追記:単発(seed1本)測定を多seed(5本)に増やしたら結論が変わった。**
> 当初の「20dBまで劣化ゼロ→10dBで崖」は seed12345 が20dBでたまたま当てていたための見え方で、
> 5seed平均では劣化の立ち上がりは **20→15dB**、傾斜はもっとなだらか。さらに**同じSNRでも
> ノイズの引き(seed)でCERが2〜3倍ブレる**。回帰テストの閾値を単発測定で引くと即フレークになる。
> 下のB-2が正(B-1は当初の単発測定として残す)。

### B-1.【参考・当初】単発(seed12345)測定 — *崖に見えた版*
**条件**: AmiVoice `-a-general` / HTTP同期 / 6ケース / 単一seed=12345 / 2026-06-11
**試行**: 24回 / **音声合計**: 91.2秒 / **再生成**: `npm run measure:snr`

| SNR | ケース平均 CER | 試行 | order-001 の認識 |
|---|---|---|---|
| clean | 7.9% | 6 | ホットコーヒーを一杯ください(0%) |
| 20dB | 7.9% | 6 | ホットコーヒーを一杯ください(0%) |
| 10dB | 24.6% | 6 | **パソコンBをいっぱいください**(71%) |
| 5dB | 27.7% | 6 | ポストコンビニを1回ください(50%) |

### B-2.【実測・本命】多seed(5本)測定 — *スロープ + フレーク版*
**条件**: AmiVoice `-a-general` / HTTP同期 / **6ケース × SNR5段 × seed5本** / Node製ノイズミキサ(実SNRは計算値)/ 2026-06-12
**試行**: 126コール / **音声合計**: 478.5秒 / **再生成**: `npm run measure:snr:robust`

| SNR | macro CER(seed間 mean±σ) | seed間レンジ | 試行 |
|---|---|---|---|
| clean | 7.9%(決定的) | — | 6 |
| 20dB | **9.5% ± 2.4pt** | 7.9〜13.5% | 5seed×6 |
| 15dB | **18.7% ± 4.9pt** | 13.5〜23.0% | 5seed×6 |
| 10dB | **20.7% ± 3.8pt** | 15.1〜24.6% | 5seed×6 |
| 5dB | **26.6% ± 3.3pt** | 21.0〜29.3% | 5seed×6 |

**ケース内のseed分散(order-001。崖の主役)**:

| SNR | CER(mean±σ) | seed別(12345/23456/34567/45678/56789) |
|---|---|---|
| clean | 0%(決定的) | — |
| 20dB | 5.7% ± 7.8pt | 0 / 14 / 0 / 14 / 0 % |
| 15dB | 45.7% ± 29.3pt | 14 / 57 / 71 / 71 / 14 % |
| 10dB | 47.1% ± 22.4pt | 71 / 36 / 57 / 57 / 14 % |
| 5dB | 41.4% ± 17.1pt | 50 / 50 / 14 / 36 / 57 % |

**読みどころ(本命・等身大の学び)**:
1. **「崖」は単発測定のまやかし**。例の「パソコンB(71%)」は10dBの**5本中の最悪引き**で、平均は47%。
   劣化の立ち上がりは20→15dBにあり、形は崖というより**ばらつきの大きいスロープ**。
2. **同じSNRでも引き(seed)でCERが2〜3倍ブレる**(order-001 15dB: 14〜71%)。
   → **単発測定でCER閾値を引くとテストがフレークする**。回帰テストとして組むなら多試行の中央値/分位点で見るべき。
3. **逆に頑健なセルは完全に決定的**。`domain-001` の5dBは5seed全部**11.5%**、`filler-001` の10dBは全部**38.1%**。
   頑健性はケース依存で、頑健な所はノイズが変わってもびくともしない。閾値は**ケース別**に持つのが妥当。

## C.【実測】エンジン比較(会話汎用 vs 音声入力向け)

> ⚠️ **2026-06-12 追記**: §B同様、単発(seed1本)の「圧勝(36.5%→14.3%)」は**差が最も開いた引き**だった。
> 多seed(5本)で測り直すと優位は残るが**圧勝ではなく、5本中2本は逆転**。C-2(多seed)が正。

### C-1.【参考・当初】単発(seed12345)測定
**条件**: `-a-general` vs `-a-general-input` / HTTP同期 / order-001,order-002,schedule-002 / clean & 10dB / 単一seed / 2026-06-11
**試行**: 12回 / **音声合計**: 39.0秒 / **再生成**: `npm run measure:engine`

| 条件 | -a-general | -a-general-input |
|---|---|---|
| clean | 3.2% | 3.2% |
| 10dB | 36.5% | **14.3%** |

### C-2.【実測・本命】多seed(5本)測定
**条件**: 同上 / 10dB を **seed5本**(同一ノイズ波形を両エンジンへ)/ 2026-06-12
**試行**: 36コール / **音声合計**: 117.1秒 / **再生成**: `npm run measure:engine:robust`

| 条件 | エンジン | macro CER(seed間 mean±σ) | seed間レンジ |
|---|---|---|---|
| clean | -a-general | 3.2%(決定的) | — |
| clean | -a-general-input | 3.2%(決定的) | — |
| 10dB | -a-general | **28.7% ± 7.7pt** | 17.5〜36.5% |
| **10dB** | **-a-general-input** | **19.8% ± 7.6pt** | 9.5〜27.8% |

**10dB seed別の対戦**(macro CER, input が勝った=低い):

| seed | -a-general | -a-general-input | 勝者 |
|---|---|---|---|
| 12345 | 36.5% | 14.3% | input |
| 23456 | 24.6% | 27.8% | **general** |
| 34567 | 31.7% | 9.5% | input |
| 45678 | 33.3% | 23.8% | input |
| 56789 | 17.5% | 23.8% | **general** |

**読みどころ(正直版)**: ノイズ下で `-a-general-input` は**平均では優位**(28.7%→19.8%, 相対約3割改善)だが、
**圧勝ではなく seed依存で、5本中2本は `-a-general` が勝った**。単発の「36.5 vs 14.3」は最も差が開いた引き。
さらに**ケース依存が強い**: `order-001` は input が大幅に改善する一方、`schedule-002` では input が
`ミーティング`→`YouTube` と**悪化**(3seedで42.9%, general は全seed 9.5%)。
→ 記事では「ノイズ下では音声入力向けが平均的に有利。ただし万能ではなくケース・条件で測って選ぶ」が正確。

> ⚠️ ドメイン特化エンジン(`-a-medgeneral` 等)は**空応答=クーポンで権限なし**のため未測定(下記G)。

## C-2.【実測】ユーザー辞書(profileWords)before/after

**条件**: AmiVoice `-a-general` / profileWords=JSON配列(`{written,spoken,classname?}`)/ HTTP同期 / 2026-06-11
**再生成**: `notes/gotchas.md` #14 の手順(`profileWords` を recognizeSync に渡す)

| ケース(条件) | 登録語 | before | after | 差 |
|---|---|---|---|---|
| order-001(10dBノイズ) | ホットコーヒー/一杯 | パソコンBをいっぱいください(71%) | (同左, 変化なし) | **0** |
| order-001(5dBノイズ) | ホットコーヒー/一杯 | ポストコンビニを1回ください(50%) | (同左) | **0** |
| 躑躅森さん…(clean) | 躑躅森(つつじもり) | 躑躅森さんに…(0%) | (同左) | **0** |
| AmiVoiceの…(clean) | AmiVoice(アミボイス) | AmiVoiceのエンジンで…(0%) | (同左) | **0** |
| 造語 ぐるぐるぺん…(clean) | グルグルペン/ぴよぴよノート | ぐるぐるペンと…(認識成功) | (同左) | **0** |

**読みどころ(正直な結果)**: 辞書の配管(JSON形式・`d`スペース区切り)を正した上で実測したが、
**今回の条件では CER 改善差は出なかった**。理由は2つ:(1) ノイズ下は音響的に語が崩れており、
単語登録(言語モデルのバイアス)では復元できない。(2) clean では `-a-general` が珍しい固有名詞
(躑躅森)・英語ブランド(AmiVoice)・造語まで**辞書なしで正解**してしまう。
辞書が効くのは「明瞭だが真にOOVな語/同音衝突」のはずだが、SAPI音声でその条件を作れなかった。
→ **記事では「辞書効果は条件依存・本検証では有意差なし」と書く**(誇張しない)。

## D.【実測】WAVフォーマット受理性(2層)

### D-1. AmiVoice 側(HTTP同期, order-001実音声, `-a-general`, 2026-06-11)
**試行**: 8回 / **音声合計**: 約24秒 / **再生成**: `npm run measure:format`

| フォーマット | 判定 | CER | 認識結果/エラー原文 |
|---|---|---|---|
| 16kHz/16bit/mono PCM(基準=lsb16k) | 成功 | 0.0% | ホットコーヒーを一杯ください。 |
| 8kHz/16bit/mono PCM | 成功 | 0.0% | ホットコーヒーを一杯ください。 |
| 44.1kHz/16bit/mono PCM | 成功 | 0.0% | ホットコーヒーを一杯ください。 |
| 16kHz/16bit/**stereo** PCM | 成功 | 0.0% | ホットコーヒーを一杯ください。 |
| **ヘッダ無し生PCM**(audio/wav詐称) | 成功 | 0.0% | ホットコーヒーを一杯ください。 |
| 空(0バイト) | **無音** | - | results空/textなし |
| ゴミバイト列(audio/wav詐称) | **無音** | - | results空/textなし |
| 不正appkey | **エラー** | - | `received illegal service authorization`(**HTTP 200**+message) |

**読みどころ**: AmiVoice HTTP同期は WAV ヘッダを読んで内部リサンプルするため、レート/チャンネルに
**非常に寛容**(8k/44k/stereo すべて成功)。一方で**認証失敗でも HTTP 200 を返し、エラーは
body の `message` に入る**(後述 gotchas#1)。不正入力はエラーではなく**無音(空応答)**に落ちる。

## E.【実測】ASR → LLM 抽出 の誤り伝播

**条件**: 上記の認識結果 → Claude `claude-haiku-4-5` で構造化抽出 → LLM-as-judge / 2026-06-11
**再生成**: `npm run measure:real`(`eval/out/real.json`)

### E-1. clean 6ケースの伝播(judge一致率 4/6 = 66.7%)
| ケース | CER | judge | 抽出アクション | 備考 |
|---|---|---|---|---|
| order-001 | 0% | ✓ | `{order, ホットコーヒー, q=1}` | |
| order-002 | 0% | ✓ | `{order, アイスカフェラテ, q=2, [ラージ]}` | |
| schedule-001 | 0% | ✓ | `{schedule, 定例会議, 来週の月曜日}` | |
| schedule-002 | 0%※ | ✓ | `{schedule, 明日の15時}` | ※digits正規化後 |
| domain-001 | 0% | ✗ | `{query, デシベルと…}` | 正解ラベルが曖昧(下記G) |
| filler-001 | 28.6% | ✗ | `{order, ホットコーヒー, **q=null**, [いっぱい]}` | ASR誤りが伝播 |

### E-2. キラー4点セット(ノイズ誘発の致命的伝播)
| 項目 | 値 |
|---|---|
| 入力音声(正解文) | ホットコーヒーを一杯ください |
| 認識結果(10dBノイズ, `-a-general`) | **パソコンBをいっぱいください**(CER 71%) |
| LLM構造化出力 | `{intent:order, item:"パソコンB", quantity:1, modifiers:[]}` |
| 期待値 | `{intent:order, item:"ホットコーヒー", quantity:1}` |

**読みどころ**: ASR が品名を `ホットコーヒー`→`パソコンB` と誤ると、LLM は**スキーマ的に妥当だが
意味は完全に誤った注文**を自信を持って生成する。`filler-001` では `一杯`→`いっぱい`(かな化)で
**数量(quantity:1)を取りこぼす**。→ **ASRの1トークンの揺れが下流の構造化フィールドを壊す**。
「ASRだけ・LLMだけのテストでは捕まらない。パイプライン全体の回帰テストが要る」の実証。

## F.【シミュレータ】劣化条件の網羅(ハーネス集計ロジックの検証)

clean合成音声では汎用エンジンが強く、ffmpeg無し・特化エンジン権限なしの制約もあるため、
**因子全網羅の集計・伝播分析ロジック**は決定的ASR誤りシミュレータで検証した(実音声の追試はG参照)。
**条件**: simulated ASR / rule-based抽出 / 6ケース×エンジン2×辞書2×SNR4×話速3 = 288行 / `npm run eval`

| 区分 | micro CER | judge一致率 |
|---|---|---|
| 汎用エンジン(モデル) | 10.9% | 86.1% |
| 特化エンジン(モデル) | 7.3% | 88.2% |
| 辞書なし(tech×汎用) | 27.0% | 83.3% |
| 辞書あり(tech×汎用) | 12.3% | 83.3% |

**誤り伝播(CER帯→judge一致率)**: 0%→100% / 0–10%→86.7% / 10–25%→77.5% / >25%→46.7%
→ 実測E(CER上昇でjudge低下)と**同じ単調傾向**を再現。
